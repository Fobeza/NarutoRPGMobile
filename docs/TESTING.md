# Тесты и инструменты

Два слоя проверок:

1. **Без браузера (Node.js 18+)** — исполняют собранный `index.html` в заглушках DOM/Canvas: секунды, годятся после
   любой правки и для CI. См. «Проверки в Node» ниже.
2. **Браузерные (Playwright)** — открывают игру в эмуляции iPhone 15 Pro, нажимают кнопки, проверяют состояние
   и снимают скриншоты (в `tools/shots/`, в git не попадают). Установка: `pip install playwright` (браузер Chromium).
   Если Playwright не установлен, `check_all.py` помечает эти наборы как пропущенные, а не как упавшие.

## Одной командой

```bash
python3 tools/check_node.py          # только проверки в Node, ~12 с — после любой правки
python3 tools/check_all.py --quick   # сборка + Node + быстрые браузерные тесты, ~3 мин
python3 tools/check_all.py           # всё: Node + 7 Python-наборов + карта + комнаты, ~12 мин — перед публикацией
python3 tools/check_all.py --node    # сборка + Node-проверки, браузер и сервер не нужны
```

`check_all.py` поднимает сервер на 8765, если его ещё нет, и завершает только свой
сервер. Его 10 этапов не включают `tools/test_*.js`. Код 0 при пропущенном
браузерном слое **не означает** полного прогона: проверяйте отсутствие пропусков.

## Полный прогон перед публикацией

Для сборки нужен Python 3; для Node-проверок — Node.js 18+. Playwright нужен
отдельно для Python и Node. Например, установка вне репозитория:

```bash
python3 -m venv "$HOME/.venvs/naruto-rpg"
. "$HOME/.venvs/naruto-rpg/bin/activate"
python -m pip install playwright Pillow
python -m playwright install chromium
npm install --prefix "$HOME/.local/share/naruto-tools" playwright
export NODE_PATH="$HOME/.local/share/naruto-tools/node_modules"
node "$NODE_PATH/playwright/cli.js" install chromium
```

Версии Python/Node Playwright могут требовать разные ревизии Chromium.
Обе установки браузера должны завершиться успешно; системные библиотеки
Chromium устанавливаются отдельно средствами вашей ОС. Pillow нужен для аудита
мастеров и импорта арта, но не для обычной сборки.

Проверенный набор (2026-10-21, полный прогон зелёный): Python 3.13, Node.js 22,
Playwright 1.56.0 для Python и для Node (Chromium 141, ревизия 1194). Если Chromium
уже установлен заранее, ставьте ту версию Playwright, которая ожидает именно его
ревизию, — иначе запуск браузера падает с «Executable doesn't exist».

В отдельном терминале (или через менеджер долгоживущих процессов):

```bash
python3 -m http.server 8765 --bind 0.0.0.0
```

Из корня репозитория, последовательно, с активным окружением:

```bash
python3 tools/check_docs.py
python3 tools/check_all.py && (
  for f in tools/test_*.js; do
    node "$f" || exit 1
  done
)
```

Сейчас отдельных JS-наборов 18; перечисление через glob подхватывает новые.
Не пересобирать HTML во время браузерного прогона. Снимки/логи хранить в
игнорируемом `tools/shots/`, а не среди мастеров `art/`.

## Проверка живой деревни

`node tools/test_sprites.js` проверяет настоящие пиксели всех 684 кадров и 57 портретов, отсутствие чужих фрагментов у героя, импортированный спрайт Фугаку, размер и линию земли, свечение окон внутри силуэта и отсутствие свечения на карнизах. Нужны Playwright для Node и запущенный сервер; используются `GAME_URL`, `CHROME_EXECUTABLE`, `PLAYWRIGHT_MODULE`. Снимки — `tools/shots/sprites/`, другой каталог можно задать через `SPRITE_SHOTS`.

`tools/node/village.js` автоматически входит в `check_node.py`. Дополнительный `node tools/test_village.js` требует пакет Playwright для Node и запущенный сервер. Он нажимает сенсорную кнопку, проходит ремонт фонаря, проверяет четыре уличные сценки, прыжки, сохранение и доступность всех комнат после поручений. Снимки — в `tools/shots/village/`.

Для установленного браузера можно передать `CHROME_EXECUTABLE`, для другого адреса игры — `GAME_URL`, для готового пакета Playwright — `PLAYWRIGHT_MODULE`. Без этих переменных используются браузер Playwright и `http://localhost:8765/index.html`.

## Проверки в Node (`tools/node/`)

`tools/node/cartography.js` проверяет кэш и обновление подложки, отсутствие изменений мира от отрисовки, группы маркеров без потерь, фильтры, доступность меток и маршрутов, сохранение цели, масштаб и настройки. `node tools/test_cartography.js` открывает настройки настоящими касаниями, приближает и двигает карту жестом, выбирает значки и ставит метку через карточку. Использует `GAME_URL`, `CHROME_EXECUTABLE`, `PLAYWRIGHT_MODULE`; снимки — в `tools/shots/cartography/`.

`tools/node/entries.js` проверяет подсказку у каждой действующей двери, отсутствие перехода при ходьбе, вход и выход по отдельному нажатию, приоритет дверей и ограничения расстояния, направления и крыш.

`node tools/test_entries.js` нажимает настоящие сенсорные и клавиатурные кнопки у дома и лавки, проверяет отсутствие входа от ходьбы и повторного перехода от удержания, выход по кнопке, силуэты животных и жесты пяти типов жителей в настоящем Canvas. Снимки и измерения — в `tools/shots/entries/`; используются обычные `GAME_URL`, `CHROME_EXECUTABLE`, `PLAYWRIGHT_MODULE`.

`tools/node/motion.js` проверяет, что новые анимации не меняют состояние и коллизии, отключаются настройкой эффектов, оставляют основания объектов на месте, уступают прогулке и ласке животных, ограничивают число кругов дождя и не переходят на другие карты.

`node tools/test_motion.js` записывает настоящие кадры жестов, книги, мяча, кошки, пса, цветов, воды и дождя; проверяет неизменность сохранения при отрисовке, отключение эффектов, число жителей и объектов, три размера экрана. Использует те же переменные `GAME_URL`, `CHROME_EXECUTABLE`, `PLAYWRIGHT_MODULE`; кадры — в `tools/shots/motion/`.

`tools/node/daily.js` проверяет повседневную жизнь: реальные UID и маршруты жителей, безопасные прогулки, животных без новых коллизий, однократную помощь и поглаживание, дождь и ночь, настройки эффектов и аудио, очистку новой игры и совместимость сохранения. Браузерный сценарий `node tools/test_daily.js` использует те же `GAME_URL`, `CHROME_EXECUTABLE` и `PLAYWRIGHT_MODULE`; снимки и кадры анимации записываются в `tools/shots/daily/`.

| Файл | Что делает |
|---|---|
| `harness.js` | Заглушки `document`/`canvas`/`localStorage`, загрузка `index.html` как модулей, запись вызовов рисования, сидируемый `Math.random`, готовое состояние героя |
| `checks.js` | 26 проверок: модули и предупреждения, целостность данных, 760 прогонов сценариев, генерация деревни на сидах, интерьеры, шрифт, 83 сцены `update`+`draw`, 20160 боёв и целевые окна баланса, сохранения |
| `balance.js` | Генератор `docs/BALANCE.md` и `docs/balance.csv` (запускается через `tools/balance.py N`) |
| `golden.js` | «Золотые отпечатки» для рефакторинга: хэш последовательности вызовов рисования в 56 боях и ~40 экранах |
| `targets.js` | Общий доступ к целевым окнам побед из `tools/targets.json` |

```bash
node tools/node/checks.js                      # базовый набор; check_node.py запускает также дополнительные
N=200 SEEDS=7,13 node tools/node/checks.js     # больше боёв на ячейку, другие сиды деревни
node tools/node/golden.js > /tmp/before.txt    # до рефакторинга
# …правка… && python3 build.py
node tools/node/golden.js > /tmp/after.txt     # после; diff должен быть пустым
```

Проверки ловят то, что не видно глазами: битые ссылки в сценариях (`jump`/`call` на несуществующую метку, друга,
врага, предмет), недостижимые двери и объекты разговора, символы вне пиксельного шрифта, падения сцен при отрисовке,
выход баланса из целевых окон, поломку сохранений.

| `test_outdoor.py` | Травы, рыбалка, сундук, продажа, травничество, крыши |

Ненулевой код выхода, ошибки JS/Traceback и строки ошибок означают провал.
Счётчик `✘ 0` в итоговой строке сам по себе не ошибка. Помощники для своих тестов — `tools/tlib.py`
(`open_page`, `seed`, `W(page, js)` — выполнить код в сцене мира, `B(...)` — в бою, `key`, `shot`, `check`,
`pick(page, подпись)` — строка меню или окна выбора по подписи; двери в мире открываются кнопкой A).

## Отладка в браузере

`http://localhost:8765/?debug=1`: счётчик FPS и сцен, рамки коллизий, тап по карте — телепорт, «Читы» в меню.
В консоли браузера доступен весь `G` — например `G.state.vars.day = 20`, `G.game.give('kunai', 5)`.
