# Полировка игры — памятка самому себе

Полировка — это **не новые системы**. Это: видно, читается, отзывается, не раздражает, работает на iPhone в портрете.
Новую механику — только если владелец попросил. Всё остальное — правила из `CLAUDE.md` (они главнее этой памятки).

## Главный цикл (одна область за проход)

1. **Посмотреть глазами до правок.** Снять скриншоты области (рецепт ниже) — минимум три экрана × день/ночь.
   Записать список замечаний с приоритетом:
   - P1 — сломано: не нажимается, текст «?» или за рамкой, перекрытие кнопок, падение, потеря прогресса;
   - P2 — мешает: мелко, не читается, неясно, куда идти, кнопка < 44 CSS-пикселей, нет отклика на действие;
   - P3 — сочность: анимация, звук, тряска, вспышка, переходы, мелкие несостыковки стиля.
   Сначала все P1 области, потом P2, P3 — в конце и только сколько влезает.
2. **Править `src/`, не `index.html`.** Потом `python3 build.py`.
3. **`python3 tools/check_node.py`** после каждой правки (~12 с). Красное — чинить сразу, не копить.
4. **Посмотреть глазами после.** Те же кадры, сравнить с «до». Тест зелёный ≠ стало лучше.
5. **Закрыть проход:** `python3 tools/check_all.py --node` (или полный с браузером), запись в `docs/CHANGELOG.md`,
   отметки в `docs/TODO.md` / `docs/ROADMAP.md`, коммит с понятным русским сообщением.

Мелкие проверенные шаги лучше одной большой правки: каждую можно откатить и объяснить владельцу.

## Как смотреть (облачная среда)

Python-Playwright обычно не установлен, а Node-Playwright и Chromium — есть. Работает так:

```bash
setsid nohup python3 -m http.server 8765 >/dev/null 2>&1 < /dev/null &      # из корня репозитория
NODE_PATH=/opt/node22/lib/node_modules node shot.js out.png                 # скрипт — ниже, класть в scratchpad
```

```js
// shot.js — снимок экрана игры в эмуляции iPhone; дальше — свои действия через page.evaluate
const {chromium}=require('playwright');
(async()=>{const b=await chromium.launch();
const c=await b.newContext({viewport:{width:393,height:759},deviceScaleFactor:2,isMobile:true,hasTouch:true});
const p=await c.newPage();const errs=[];p.on('pageerror',e=>errs.push(String(e)));
await p.goto('http://localhost:8765/?debug=1');await p.waitForFunction(()=>window.G&&G.scenes);
// пример: await p.evaluate(()=>{ /* seed как в tools/tlib.py, затем G.scenes.push(G.scenes.make('status')) */ });
await p.waitForTimeout(800);await p.screenshot({path:process.argv[2]});
console.log('сцена',await p.evaluate(()=>G.scenes.top()&&G.scenes.top().name),'ошибки',errs);await b.close();})();
```

Python-Playwright для `tools/test_*.py` и полного `check_all.py` ставится версией под имеющийся Chromium
(`/opt/pw-browsers/chromium-1194` ↔ `pip install playwright==1.56.0`); новее — ищет браузер, которого нет.
Node-тесты `tools/test_*.js` запускать с `NODE_PATH=/opt/node22/lib/node_modules`.
Пока идёт `check_all.py`, **не пересобирать** `index.html` — тесты подхватят полусобранное.

Затем открыть PNG через Read и **действительно рассмотреть**. Готовое состояние героя — `seed()` в `tools/tlib.py`
и в `tools/test_release2.js` (там же — касание кнопки по подписи, смена размеров и плотности).

Без браузера: `node tools/node/render.js /tmp/out` — программный рендер меню, сумки, статуса, журнала, магазина, титула.
Комнаты — `python3 tools/audit_rooms.py --shots`, карта — `python3 tools/render_map.py /tmp/map.png`,
персонажи — `python3 tools/render_chars.py /tmp/c.png naruto,sasuke`.

### Матрица кадров

- Экраны: **320×568** (маленький), **393×759** (iPhone 15 Pro), **430×932** (большой); плотность `big/mid/fine`
  (`G.storage.settings.density`, затем `G.screen.resize()`).
- Обязательно плотность ×2 (iPhone SE 375×667, XR/11 414×896): там масштаб 1 CSS-пиксель на точку и экран
  самый широкий — так нашлась пустая полоса снизу (`MAX_H`). Матрица из 5 телефонов × 11 экранов — ~5 минут.
- Время: день 540, закат 1080, ночь 1320 (`G.state.vars.min`); плюс дождь.
- Настройки, которые ломают раскладку: левша (`lefty`), размер кнопок 1.4 (`buttonSize`), мини-карта выкл., эффекты выкл.
- В консоли доступен весь `G`; `?debug=1` — FPS, рамки коллизий, телепорт тапом, «Читы» в меню.

## Чек-листы по областям

**Интерфейс и текст**
- Рамки, кнопки, шкалы — только из `G.ui` (`panel, button, gauge, title, tab, scrollbar, menu, card…`), без ручных рамок.
- Каждый символ — из пиксельного шрифта. «?» на экране = нет глифа → `tools/make_font.py`, не замена текста наугад.
- Текст не вылезает за панель на 320×568; длинные строки переносятся; у списков есть видимая прокрутка.
- Зоны касания ≥ 44 CSS-пикселя, не пересекаются; «Назад» всегда в одном месте; у каждого действия есть отклик.
- Один термин — одно слово везде (рё, чакра, Фокус…); единообразно «ё»; без канцелярита. Диалоги — язык `docs/SCRIPTS.md`.

**Мир**
- Порядок по глубине: персонаж за деревом/крышей, тени от источника, свет не проходит сквозь стены (`world/lighting.js`).
- NPC не стоят в дверях и друг в друге; подсказка у каждой двери; цель задания понятна по стрелке/мини-карте.
- Ночь читаема (не «чёрный экран»), окна светятся по маскам, дождь не прячет героя.

**Бой** (`scenes/battle.js`, `battle_fx.js`, `battle_ai.js`, `battle_tactics.js`)
- Каждый удар заметен: вспышка/откидывание/число; ясно, чей ход и что задумал противник.
- Правка цифр → `python3 tools/balance.py 120`, окна побед — `tools/targets.json`; `docs/BALANCE.md` не трогать руками.
- Рефакторинг отрисовки боя/сцен → `node tools/node/golden.js` **до** и после, `diff` пустой. Визуальное изменение
  намеренно меняет отпечатки — тогда сказать об этом в коммите.

**Звук и ощущение** — `engine/audio.js`: короткие звуки на касание, удар, получение предмета; без наложения каши.
Анимации уважают «эффекты выкл.» (`tools/node/motion.js` это проверяет) и не меняют состояние/коллизии.

**Производительность** — 60 кадров на iPhone: кэш подложек, без пересоздания холстов в `draw`. Время кадра мира
меряет `tools/test_release2.js`; после «сочных» правок посмотреть FPS в `?debug=1`.

## Ловушки (проверено на этом проекте)

- Браузерные тесты нажимают кнопки **по подписи** (`tap('Вперёд')`, `'В план +'`, `'В бой!'`). Переименовал кнопку —
  `grep` по `tools/` и поправь тесты в том же коммите.
- Новый файл — в `JS_FILES` в `build.py`, порядок важен. Новое поле сохранения — в `defaults()` в `systems/game.js`.
- Отрисовка не должна менять `G.state` (проверяется: снимок JSON до/после `draw`).
- Не «улучшать» то, что не видел на скриншоте. Не трогать сюжетные флаги ради красоты.
- `docs/BALANCE.md`, `index.html`, корневой `sw.js` — генерируются.

- Сюжет мешает снимкам: без характеристик героя мир открывает `iruka_retest`. Для чистого кадра — `seed()` из
  `tools/tlib.py` (статы и навыки) и `G.story.poll=()=>false`, мир — `G.scenes.push(G.scenes.make('world', pos))`.
- Падение теста сначала сверить с исходной сборкой: `git show HEAD:index.html` в отдельную папку, сервер на 8766,
  тот же тест с другим адресом. Так отличаются свои поломки от старых.
- Полный `check_all.py` зелёный с 2026-10-21. Новый тест — выбор пунктов меню и окон по подписи:
  `pick(page, 'Сумка')` из `tools/tlib.py` (у сцен `menu` и `pick` есть `labels()`), двери — кнопкой A.
- Плотность по умолчанию зависит от телефона (`autoDensity`): эмуляция 393×759 ×2 без выбора получает «крупно».
  Тесты под раскладку фиксируют «мелко» (`tlib.open_page`, `test_cartography.js`); новый тест — так же.

## Как отчитываться владельцу

По-русски, кратко: что было (скриншот «до»), что стало («после»), какие проверки зелёные, что осталось в списке.
Скриншоты класть в рабочую папку или scratchpad и показывать, а не описывать словами.

### Подключённый арт 2.2.2

- Мастеры `art/environment` и `art/terrain/path` → `tools/import_environment.py` → `src/gfx/environment_art_data.js`. Не грузить мастеры асинхронно и не подставлять их пиксельные размеры как игровые.
- Проверка `tools/test_environment_art.js` фиксирует геометрию исходной Конохи, альфа/опоры 30 спрайтов и направления дорог; сниматель `tools/capture_environment.js`. При изменении пикселей golden может остаться прежним, поскольку записывает drawImage и размеры, а не содержимое изображений. Нужны настоящие кадры Canvas.
- Дальше: читаемость маленьких цветов, скрытый ствол низкого дерева, дополнительные виды дороги при появлении новых топологий. Все текущие коллизии сохранять; отменённую оштукатуренную ограду не возвращать.

### Каменное мощение 2.2.2

- `street_art.js`: только уличные MAINROAD/STONE/COBBLE/PLAZA и природные кромки, без правок карты. Период текстуры и неровностей должен совпадать с фазой ключа кэша. Не использовать случайные независимые края клеток.
- `tools/test_street_art.js` проверяет реальные пиксели и оставляет `tools/shots/stone-streets/seams.png`; дополнительно смотреть прямые, угол, перекрёсток и площадь в кадрах настоящей камеры, день/ночь на трёх телефонах. Golden не проверяет содержимое изображений.
- Следующие материалы (не сделано): дерево, песок/гравий/берег, скалы, интерьерные полы. Не размывать архитектурные пороги и не менять коллизии; пять утверждённых генераций тропинок сохранять.

### Согласованный следующий проход

- Сделано: P2 «Назад» в статусе, журнале и календаре; `test_navigation.js`, `capture_navigation.js`, сравнения в `tools/shots/navigation/`. Опция `roomyBack` включается только после адаптации сцены.
- Осталось P2: карта, склад, создание персонажа/служебные окна; длинные тексты и остальные небольшие элементы требуют отдельной проверки. Боевой интерфейс пока не менять.
- Осталось P3: читаемость цветов, скрытый ствол низкого дерева, масштаб кустов; основания зданий/пороги/примыкания; мягкий ночной свет с читаемыми персонажами. Вода/мелководье/редкий береговой декор выполнены отдельным проходом ниже. Лесные массивы в выбранный пользователем проход не входят.
- Сохранять реальные игровые размеры и коллизии. Не объявлять весь проход завершённым после одного этапа.

### Вода и берега 2.2.2

- `water_art.js`: уличная вода запекается в существующие чанки, расстояние до берега берётся из соседних клеток. Рисунок привязан к мировым координатам; не добавлять независимый шум от начала каждого тайла.
- Природные кромки отличаются от камня/настилов. Камыш/камни — пиксели воды, не новые объекты/коллизии. Рябь уважает настройку эффектов. Внутренние водные покрытия не заменены.
- `test_water_art.js` проверяет именно воду. Первый смешанный тест всех старых тайлов обнаружил зависимость трёх пикселей суши от обратного порядка рисования — на исходной и новой сборках одинаково (3/3). Не объявлять это регрессией воды; тест воды изолирован от старого декора суши.
- `capture_water.js`: берег, настил у воды, парк × три телефона × день/ночь. Проверять общую фазу, внутренние/внешние углы, мягкость мелководья, чёткую границу мостов, отсутствие декора посреди глубокой воды.
- Дальше остаются растения, основания зданий/пороги, ночное освещение и другие окна. Текущий проход их не меняет.

### Исправление воды после замечания владельца

- Широкий зелёный градиент 15/7 выглядел как свечение; прежняя положительная визуальная оценка была ошибочной. Теперь кромка общая, голубая, 5 точек с пиксельным дизерингом. Не возвращать размытый зелёный ореол.
- Цвет нельзя резко выбирать по типу ближайшей суши: на границе камня/травы это давало пятна. Тип суши используется только для размещения берегового декора.
- Непрерывность и контраст фактуры — разные проверки. `test_water_art.js` сверяет каждый пиксель с мировым образцом; допустимый контраст коротких штрихов не считать швом.
- Сравнения `tools/shots/water-fix/`: смотреть озеро с островом, искусственную набережную, ночь на 320px. Дальнейший список растений/зданий/света/окон остаётся прежним.

### Мобильный редактор карт

- `src/editor/phone.*` → `tools/build_phone_editor.py` → публичный `map-editor.html`. Включены только общие графические модули, игровой цикл и система сохранений не загружаются.
- Проверять 320px: пять инструментов помещаются без обрезанных подписей; два пальца отменяют пробную точку кисти. Проверять JSON/PNG/HTML, загрузку из файла и восстановление черновика. `tools/test_phone_editor.js` использует реальные касания.
- Редактор — отдельный новый инструмент, сравнения с игровой картой «до/после» не нужны: игра не изменена. Кадры пустого и заполненного редактора в `tools/shots/editor/`.
- Осталось для отдельных согласованных этапов: заливка областей, игровой импорт с дверями/коллизиями/проверкой маршрутов, NPC и сюжетные точки. Пока не называть JSON готовой игровой локацией.

### Размеры и перенос в редакторе

- До 96×96 клеток; расширение сохраняет левый верхний угол и данные, обрезка только после подтверждения. Снимок undo обязан восстанавливать и клетки, и объекты.
- Pending-перенос не меняет модель до pointerup. pointercancel/выход за карту/второй палец отменяют пробное размещение. Предпросмотр использует те же bounds/paintObject, что PNG и постоянный рисунок.
- Масштаб 0.5–2, flipX/flipY; новый JSON v2 читает v1. Не считать рамку визуального спрайта игровой коллизией. Не менять игру при разработке редактора.
- `test_editor_transform.js`: касания 320/393/430, клетки, перенос/отмена, пиксели PNG, сохранность при resize и миграция. Остались заливка и игровой импорт, не трансформации.
